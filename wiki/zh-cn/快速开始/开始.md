# 开始前的准备


## 选择你的 API

MMCR 当前提供两种方式来把你的自定义机器加入到游戏中:

 - **Java API**: 使用 MMCR 提供的公共 API ，订阅事件，编写 Java 代码来向游戏添加你的机械
 - **KubeJS集成**: MMCR 提供完整的KubeJS集成，你可以通过 KubeJS 脚本，在正确的时机调用 MMCR 提供的函数和事件，进而向游戏添加你的机械

## 我应该使用哪种 API

实际上两种 API 各有劣势:

 - KubeJS 集成使用非标准的 JavaScript 语言，意味着在多数 IDE 中没有智能提示，并且调试难度较高
 - KubeJS 无法使用 MMCR 的自定义 Render 功能，这个功能由 Java API 独占
 - KubeJS 并不**适合**自定义 tick 功能的编写，它需要大量的 `loadClass` 才能发挥非常好的效果
 - Java API 无法动态重载配方和结构，意味着你必须重启游戏才能看到更改的效果
 - Java API 必须依靠 `service loader` 才能向游戏注册多方块机器(这对开发的影响其实并不大)

完全消除这些劣势是一个涉及 `lifecycle` 和 `sync` 的复杂问题
