# 工厂控制器等级 UI 与失败原因设计

## 范围

让工厂控制器界面与普通控制器界面显示一致的机器等级信息，并在任意配方因机器等级不满足要求而无法启动时，将两种界面的上次失败原因统一显示为“等级不足”。不调整等级匹配、配方筛选、JEI 展示或其他失败原因。

## 等级显示

`FactoryControllerScreen` 在状态区域渲染控制器当前已匹配的等级快照，位置与普通 `MachineMenuScreen` 的等级行一致：状态信息之后、上次失败原因之前。每个等级类型单独一行，格式和本地化样式沿用普通控制器，例如：

`热能冶炼线圈: 铁块`

控制器未匹配到任何等级时不显示等级行。

工厂菜单客户端通过控制器位置解析客户端已同步的 `MachineControllerBlockEntity`，读取其机器等级快照。等级快照继续由现有控制器状态包同步，不向工厂快照重复加入等级字段。

## 失败原因与同步

等级不匹配产生的 `LevelInsufficientFailure` 映射至新增的失败翻译键，其文本固定为“等级不足”。不附加具体等级类型、实际等级或要求等级。

普通控制器菜单将该键加入 `MachineControllerMenu` 的 `DataSlot` 编码和解码。工厂控制器菜单将相同键加入 `ControllerMenuState` 的共享编码和解码；工厂菜单现有快照优先、菜单数据槽回退的读取规则保持不变，确保服务端开放界面期间的最新失败状态同步到客户端。

失败原因是短暂运行状态：不写入控制器或工厂调度器 NBT。区块卸载、世界重载或重新打开菜单后，失败原因依现有配方搜索过程重新产生，不会持久化过期的“等级不足”。机器等级本身仍由既有控制器状态同步路径更新，工厂 UI 不保留第二份缓存。

## 验证

- 更新普通控制器菜单测试，验证等级失败键的服务端数据槽编码和客户端解码。
- 更新工厂控制器菜单/界面测试，验证同一失败键可由共享菜单状态读取，且工厂 UI 读取已同步控制器等级显示文本。
- 保留现有失败键的行为。
- 运行相关单元测试及 `./gradlew compileJava --no-daemon`。
