# 共享多方块 IO 资源域设计

## 目标

允许多个已成型多方块共享特定的状态性 IO 部件，同时保证结构归属、异步候选计算、配方启动、持续资源消耗与输出提交不会发生重复访问、双重消耗或长期饥饿。

本设计覆盖多联高炉等共享能量、物品或流体端口的场景。普通 casing 仍可在几何上重叠，不建立归属关系。

## 组件共享策略

状态性 BlockEntity 组件声明以下策略：

- `EXCLUSIVE`：一个已成型控制器独占。第二个候选结构使用该组件时，结构形成失败。
- `SHARED_SERIALIZED`：允许多个控制器使用。所有因共享组件连通的控制器归入同一资源域，其真实 IO 访问由协调器串行提交。

首版将有绑定、能力或调度语义的组件纳入 claim，例如 IO 端口、并行控制器和工厂调度器。普通结构方块不建立 claim。

## 结构归属

`StructureClaimRegistry` 按世界维护状态性组件位置到控制器位置集合的归属关系。

形成采用两阶段提交：

1. 控制器完成结构、端口数量和 Tier 校验，并收集候选状态性组件。
2. Registry 验证全部候选 claim：已归属的 `EXCLUSIVE` 组件使本次形成失败；`SHARED_SERIALIZED` 组件允许增加 owner。
3. 验证全部通过后，批量写入 claim 并重建受影响资源域。
4. 只有 claim 提交成功后，控制器才形成、收集组件、绑定端口外观并允许配方调度。

任一步失败都不得留下部分 claim 或部分端口绑定。冲突错误需要记录冲突组件和已占用控制器位置。

拆解、方块移除或控制器移除时，先停止该控制器的活跃 lane 并递增 `structureVersion`，然后只释放属于该控制器的 claim。共享端口仍有 owner 时不得清除其绑定外观或可用状态。

区块临时未加载不会释放 claim，只暂停相关 lane；实际移除或卸载才解除归属。

## 资源域

资源域是由 `SHARED_SERIALIZED` 组件连接出的控制器连通分量。若 A 与 B 共用端口 P、B 与 C 共用端口 Q，A、B、C 必须属于同一域。

每个域维护：

- 稳定的 domain ID。
- 随 owner 或端口拓扑变化递增的 generation。
- 启动事务游标与运行期公平供给游标。

形成、拆解、端口移除和 owner 集合变化均会重建受影响连通分量，并使旧域 generation 失效。携带旧 generation 的异步候选计划必须在提交时被丢弃和重算。

## 配方事务

异步工作仅可生成不可变的候选计划，不能访问真实 BlockEntity 能力。计划至少包含 controller/lane 标识、`structureVersion`、资源域 generation、配方、理论并行数、输入输出需求和每 tick 资源需求。

真实物品、流体、能量能力只允许在服务端主线程的 `SharedIoCoordinator` 中访问。

### 启动

协调器按资源域的启动游标处理空闲 lane 请求：

1. 复核控制器成型状态、lane 空闲状态、`structureVersion`、资源域 generation 和端口归属。
2. 在真实 IO 上重新模拟输入、输出容量和可供给并行数。
3. 以实际可提交的部分并行数扣除输入并创建 active lane。
4. 游标移动到本次成功请求之后。

因此，理论并行 8 的请求在资源只够 3 份时以并行 3 启动。多个请求竞争有限库存时，总提交量不能超过真实可用量，后续请求从游标后的 lane 开始，避免固定顺序长期偏向某台机器。

### 运行与完成

每 tick，协调器按资源域运行期游标轮转活跃 lane：

1. lane 请求本 tick 所需能量和持续流体等资源。
2. 仅在获得足额资源后推进进度。
3. 资源不足的 lane 只暂停本 tick，不倒退、不额外消耗资源。
4. 每个成功获得资源的 lane 都推动游标，下一 tick 从其后开始。

配方完成的输出也经协调器提交。输出容量不足时，lane 保持完成待输出状态，不能丢失产物或结束配方。

## 生命周期失效

控制器或端口的 claim/资源域发生变化时：

- 旧 generation 的启动计划静默失效，下一 scheduler tick 重算。
- 活跃 lane 在下一 tick 重新确认资源域，不再使用旧端口快照。
- 结构变更不会造成重复消耗、重复产出或悬挂绑定。

单控制器且无共享 IO 的路径保持现有行为，不经过跨控制器竞争调度。

## 验收标准

1. 两台高炉共享 `SHARED_SERIALIZED` 能量口时均可形成；其中一台拆解后，另一台仍保有端口外观和资源访问。
2. 两台高炉共享 `EXCLUSIVE` 输入口时，后形成的控制器被拒绝，并报告冲突端口和占用控制器。
3. 两个控制器、多个 factory lane 争用仅够 10 份的共享输入，并各请求并行 8 时，启动总并行数为 10，不重复消耗。
4. 连续启动竞争下，启动游标轮转，两个控制器均可获得资源。
5. 活跃 lane 共享有限能量时，每 tick 总提取量不超过端口能力；未获足额供给的 lane 不推进；轮转后各 lane 均能推进。
6. 运行时破坏共享端口、拆解任一控制器或卸载涉及区块时，不崩溃、不重复产出、不遗留错误端口绑定，旧 generation 计划不能提交。
7. 无共享 IO 的既有单控制器和 factory parallel 行为不发生变化。
