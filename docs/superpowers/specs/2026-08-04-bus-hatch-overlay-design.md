# Bus/Hatch Overlay Model Design

## Goal

Refactor the bus and hatch asset approach to match the reference/mmce layering model: a reusable base casing layer plus a separate overlay layer. This replaces the current generated-composite texture approach with normal Minecraft block model composition.

## Scope

- Build the reusable overlay model system only.
- Apply the system to the currently registered bus/hatch categories when implemented: item input/output bus, fluid input/output hatch, and energy input/output hatch.
- Do not add unregistered MMCE tiers, ME buses, upgrade buses, or new gameplay blocks in this pass.
- Keep existing composite PNG files unless a later implementation step confirms they are no longer referenced.

## Recommended Approach

Use a new generic parent model, `assets/mmcr/models/block/bus_hatch_overlay.json`, rather than reusing the controller-specific parent model.

The parent model should define two full-cube elements:

- Base element: references `#bg_all`, uses `tintindex: 1`, and provides the casing layer.
- Overlay element: references `#ov_all`, has no tint, and provides the bus/hatch icon layer.

Each concrete bus/hatch block model should be generated by datagen and only bind textures:

- `bg_all`: `mmcr:block/basic_casing`
- `ov_all`: the matching overlay texture, for example `mmcr:block/overlay_item_input_bus`

## Texture Naming

Use MMCE-style normal overlay texture names under `assets/mmcr/textures/block/`:

- `overlay_inputbus_normal.png`
- `overlay_outputbus_normal.png`
- `overlay_fluidinputhatch_normal.png`
- `overlay_fluidoutputhatch_normal.png`
- `overlay_energyinputhatch_normal.png`
- `overlay_energyoutputhatch_normal.png`

The existing non-overlay texture names may remain during migration to avoid breaking unknown references.

## Datagen Model Naming

Use `ModelGen` to generate block model names matching the current block/resource naming style into `src/generated/resources`:

- `item_input_bus.json`
- `item_output_bus.json`
- `fluid_input_hatch.json`
- `fluid_output_hatch.json`
- `energy_input_hatch.json`
- `energy_output_hatch.json`

## Validation

- Resource paths should resolve without missing-model or missing-texture warnings.
- Block models should render as base casing plus overlay, not as pre-composited PNGs.
- Existing registered block IDs should keep their current model names unless current blockstate files prove otherwise.
- Java/Gradle changes should stay limited to datagen code needed to emit the generated resources.
