# 工厂处理器控制器 UI 设计

## 目标

当多方块结构安装工厂处理器时，控制器 UI 不显示实时并行数或并行上限。多个线程会竞争输入、输出与并行预算，因此不能将各线程并行数相加展示为一个稳定指标。

工厂模式下只显示：

- 已安装的并行控制器数量。
- 当前线程数，即工厂处理器可调度的线程容量。

未安装工厂处理器时，维持现有的“当前并行数 / 最大并行数”显示。

## 线程数语义

“当前线程数”是 `FactorySchedulerBlockEntity.threadCount()` 的值：基础线程 1 加线程分配器物品数量。这是由工厂处理器库存直接决定的稳定容量，不是 `activeLaneCount()` 所表示的动态运行线程数。

## 数据流与同步

控制器菜单新增一个 `DataSlot`，服务端读取关联工厂处理器的 `threadCount()`；没有工厂处理器时槽值为 0。客户端菜单通过该数据槽读取线程数，不通过客户端 `MachineControllerBlockEntity` 或工厂处理器库存重新计算。

这样沿用已有控制器菜单的服务端到客户端容器同步机制，并避开客户端结构组件未完整同步时产生的错误状态。

线程容量不在 `MachineControllerBlockEntity` 中持久化。其来源库存已由 `FactorySchedulerBlockEntity` 持久化，因此新增镜像字段会造成双写与存档陈旧风险。菜单 DataSlot 是临时 UI 同步数据，无需存档。

## UI 规则

- 结构未成型时：不显示并行仓、并行数或线程数。
- 结构已成型、无工厂处理器时：若安装了并行控制器，显示并行仓数量；始终显示当前并行数与最大并行数。
- 结构已成型、有工厂处理器时：若安装了并行控制器，显示并行仓数量；显示“当前线程数: xxx”；不显示并行数或并行上限。

新增中英文翻译键用于线程数标签。

## 测试

- 菜单数据槽测试：线程数从服务端槽同步到客户端菜单，并且客户端存在未完整同步的控制器实体时仍使用数据槽。
- UI 助手测试：工厂模式选择线程数行而非并行数行；普通模式继续选择并行数行。
- 保留并行数与菜单显示的既有回归测试。

## 范围

本变更仅调整控制器菜单 UI。Jade 保持现有行为，不修改其数据提供器或提示信息。
