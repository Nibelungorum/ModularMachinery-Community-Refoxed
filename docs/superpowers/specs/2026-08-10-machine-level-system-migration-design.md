# 机器等级系统迁移设计

## 目标

将 `feat/machine-level-system` 的机器等级功能安全迁移到当前主分支，同时保留主分支已有的配方暂停、运行上下文持久化、流体路由恢复和菜单行为修复。未使用等级功能的机器必须保持现有行为不变。

## 迁移方式

不直接合并等级 worktree。以主分支为基线，逐项迁移 API、结构解析、配方门槛、运行时 modifier、KubeJS 和 JEI 集成；每个与控制器或配方状态有关的冲突点均以主分支现有逻辑为基础接入等级数据。

## 等级注册与 KubeJS 生命周期

`MachineLevelRegistry` 只接受启动期注册：KubeJS 加载 startup scripts 前开启注册，在全部启动脚本完成后冻结。服务器资源重载不会清空或更改等级定义。

KubeJS 暴露与文档一致的接口：`MMCR.levelTypes.create(id)`、`MMCR.levels.create(id)` 和 `MMCR.levelSlot(typeId)`。等级构建器以声明的方块状态生成代表物品，供 JEI 显示。

## 结构与控制器状态

结构定义中的 `LevelSlot` 接受指定类型的任意已注册等级。控制器成型时解析每种类型的实际等级；同一类型的多个槽位必须为同一个具体等级，混级会阻止成型。没有等级槽位的结构保持当前结构匹配结果。

控制器将已解析等级保存到 NBT。区块或服务端恢复活动配方时先恢复此快照，正常结构检查后再以当前结构解析结果覆盖它。

## 配方和运行时效果

配方可选声明 `LevelRequirement(typeId, levelId)`。搜索时仅对包含等级要求的候选配方检查实际等级 priority 是否满足要求；无等级要求的配方保持当前搜索语义。满足输入的更高优先级候选若等级不足，会阻止回退到较低优先级候选。

等级 modifier 只在控制器已解析等级时参与计算。持续时间、能耗和产出 multiplier 相乘，parallelism 与 factory thread bonus 相加，应用顺序位于普通配方 modifier 与结构 modifier 之前。未解析等级时使用原有计算路径。

## JEI 与验证

JEI 仅为存在等级要求的配方添加等级要求行，并显示代表物品和名称。没有等级要求的配方布局不变。

实施后运行一次 `compileJava`，以及覆盖等级注册、KubeJS、结构成型、配方门槛、modifier、NBT 恢复、JEI，并包含近期暂停与恢复行为的针对性测试。所有验证均在主分支执行。
